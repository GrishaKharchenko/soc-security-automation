# SOC Security Automation

Набор инструментов автоматизации типовых задач SOC-аналитика и первичного
реагирования на инциденты. Personal cybersecurity project — учебный, но
написанный по правилам рабочего кода: модульная архитектура, конфигурация
через `.env`, логирование, обработка ошибок и тесты в каждом модуле.

---

## Инструменты

| Проект | Язык | Что делает | Статус |
|---|---|---|---|
| [**IOC Analyzer**](projects/ioc-analyzer/) | Python | Разбор фидов с индикаторами компрометации, нормализация и дедупликация, обогащение через VirusTotal, расчёт вердикта, отчёты в JSON/CSV | ✅ готов |
| **SOC Log Analyzer** | Python | Разбор логов аутентификации Windows/Linux, детект brute-force и password spraying, корреляция событий, маппинг на MITRE ATT&CK | 🔜 в планах |
| **Linux Incident Triage** | Bash | Сбор DFIR-артефактов с Linux-хоста при подозрении на компрометацию, проверка типовых механизмов закрепления | 🔜 в планах |
| **SOC Automation Toolkit** | Python | Единая CLI-оболочка над всеми модулями, общий формат результатов и общее ядро | 🔜 в планах |

## IOC Analyzer

Принимает «грязный» фид в TXT или CSV, определяет тип каждого индикатора
(IPv4, IPv6, домен, URL, MD5, SHA1, SHA256), приводит к канонической форме,
схлопывает дубликаты, обогащает через VirusTotal API v3 и выдаёт объяснимый
вердикт с risk score.

```bash
cd projects/ioc-analyzer
pip install -r requirements.txt
python -m ioc_analyzer analyze -i data/sample_iocs.txt --offline
```

Ключевые решения: проактивный rate limiting вместо ловли HTTP 429, разделение
технического статуса запроса и вердикта (сбой API никогда не даёт «чисто»),
пороги детектов вместо реакции на один сработавший антивирус.

## Как устроен репозиторий

```
soc-security-automation/
├── README.md              это оглавление
└── projects/
    └── ioc-analyzer/      каждый инструмент — самодостаточный проект
        ├── README.md          своя документация
        ├── requirements.txt   свои зависимости
        ├── ioc_analyzer/      код
        ├── tests/             свои тесты
        └── data/              свои тестовые данные
```

Каждый проект запускается, тестируется и читается независимо от остальных.
Общая библиотека появится только тогда, когда один и тот же код реально
понадобится в нескольких инструментах, — преждевременная абстракция дороже
дублирования.

## Безопасность тестовых данных

В репозитории нет реальных вредоносных индикаторов, эксплойтов и
деструктивных команд. Примеры построены на зарезервированных диапазонах и
именах из RFC 5737, RFC 3849, RFC 2606 и RFC 6761, хешах пустого файла и
хеше EICAR — официального безвредного тест-файла антивирусной индустрии.
Логи и артефакты для будущих модулей будут синтетическими.
