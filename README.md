# SOC Security Automation

Набор инструментов автоматизации типовых задач SOC-аналитика и первичного
реагирования на инциденты. Personal cybersecurity project — учебный, но
написанный по правилам рабочего кода: модульная архитектура, конфигурация
через `.env`, логирование, обработка ошибок, тесты и документация в каждом
модуле.

**351 тест**, вся сеть в тестах замокана, тестовые данные синтетические.

---

## Инструменты

| Проект | Язык | Что делает | Тесты |
|---|---|---|---|
| [**IOC Analyzer**](projects/ioc-analyzer/) | Python | Разбор фидов с индикаторами, нормализация и дедупликация, обогащение через VirusTotal, объяснимый вердикт с risk score | 168 |
| [**SOC Log Analyzer**](projects/log-analyzer/) | Python | Разбор логов аутентификации Linux/Windows, 9 правил детектирования, корреляция в инциденты, маппинг на MITRE ATT&CK | 91 |
| [**Linux Incident Triage**](projects/linux-triage/) | Bash | Сбор 45+ DFIR-артефактов с подозреваемого хоста, 8 групп проверок, работа только на чтение | 44 |
| [**SOC Automation Toolkit**](projects/soc-toolkit/) | Python | Единая CLI над всеми модулями, общий формат находок, кросс-инструментальная корреляция | 48 |

## Главный сценарий

Три инструмента по отдельности видят свой срез. Оболочка связывает их находки
по общим сущностям:

```bash
cd projects/soc-toolkit
python -m soc_toolkit run \
    --iocs samples/incident_iocs.txt --offline --include-clean \
    --logs ../log-analyzer/data/auth.log --year 2026 \
    --triage-report ../linux-triage/samples/findings.json
```

## Быстрый старт

```bash
git clone https://github.com/GrishaKharchenko/soc-security-automation.git
cd soc-security-automation
git checkout claude/ioc-analyzer-soc-98gwly
```

Каждый проект запускается независимо:

```bash
cd projects/ioc-analyzer
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m pytest
python -m ioc_analyzer classify -i data/sample_iocs.txt
```

Подробные инструкции — в README каждого проекта. Сводная инструкция по
локальному запуску всего набора: [`docs/LOCAL_SETUP.md`](docs/LOCAL_SETUP.md).

## Как устроен репозиторий

```
soc-security-automation/
├── README.md                  это оглавление
├── docs/
│   ├── LOCAL_SETUP.md         запуск всего набора на своей машине
│   └── VERIFICATION.md        план проверки и результаты прогона
└── projects/
    ├── ioc-analyzer/          каждый инструмент — самодостаточный проект
    ├── log-analyzer/          со своим README, зависимостями и тестами
    ├── linux-triage/
    └── soc-toolkit/           оболочка, объединяющая остальные
```

Каждый проект читается, запускается и тестируется независимо. Оболочка
подключает соседние проекты, но остальные три о ней не знают и работают сами
по себе.

## Сквозные принципы

Одни и те же решения проведены через все проекты — это и есть то, что делает
набор набором, а не тремя случайными скриптами.

**Отсутствие данных ≠ отсутствие проблемы.** Сбой API не даёт вердикт «чисто»,
недоступный без root артефакт помечается явно, неполный сбор не выглядит как
пустой результат. Ошибка, замаскированная под благополучие, опаснее видимой
ошибки.

**Каждая находка объяснима.** У вердикта есть причины, у техники ATT&CK —
обоснование выбора, у находки триажа — конкретное доказательство. Вывод,
который аналитик не может проверить, он перестанет читать.

**Пороги — конфигурация, а не константы.** У разных команд разная
толерантность к ложным срабатываниям, и менять её правкой исходников нельзя.

**Критичность и уверенность разведены.** Это разные оси: вход в три часа ночи
потенциально критичен, но уверенность в нём низкая. Сведение их в один
показатель теряет информацию, нужную для приоритизации.

**Осмысленные коды возврата.** 0 — чисто, 1 — есть находки, 2 — критические,
3 — ошибка запуска. Это превращает инструменты в кирпичики пайплайна.

**Контрпримеры в тестовых данных.** В каждом наборе есть легитимное поведение,
похожее на атаку. Детект, срабатывающий на что угодно, бесполезен, и без
контрпримеров этого не увидеть.

## Безопасность

В репозитории **нет** реальных вредоносных индикаторов, эксплойтов,
деструктивных команд и настоящих логов.

* адреса — из документационных диапазонов RFC 5737 и RFC 3849;
* домены — из зарезервированных зон RFC 2606 и RFC 6761;
* хеши — пустого файла и EICAR, официального безвредного тест-файла
  антивирусной индустрии;
* логи и артефакты хоста — синтетические, созданы генераторами в репозитории;
* Bash-скрипт триажа работает **только на чтение** и ничего не изменяет на
  исследуемой системе; это закреплено тестом с файлом-канарейкой.

`.env` с ключами API в `.gitignore`; API-ключ маскируется в логах фильтром.
